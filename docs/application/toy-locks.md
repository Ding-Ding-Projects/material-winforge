# Desktop toy locks and Support Tickets

The desktop design reference defines the same every-rendered-target toy-lock contract as the landing surface: a reusable anchored **Lock this element…** wizard reached from each target's context menu and keyboard path, exact target IDs, independently salted local UX hashes, selectable unlock duration, locked-state disclosure in search and palette, relock, and a self-service local application-data recovery path. The lock is explicitly for fun and is not security, encryption, authentication, or deletion.

The matching desktop reference keeps **Edit appearance…** beside **Lock this element…**. A locked target stays visible and discoverable, and the wizard names the exact target before accepting its own credential. Support Tickets and recovery are preserved as local UX copy; the app does not contact a service or delete its application-data folder.

Support Tickets is a local fictional desk. It records only bounded recovery notes and explains that no network request, remote ticket, data collection, or human support channel exists. The user opens the local application-data folder and performs deletion themselves; the app never silently deletes it.
